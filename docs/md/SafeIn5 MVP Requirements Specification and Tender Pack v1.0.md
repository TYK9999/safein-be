## Legend & Principles

| MoSCoW Priority | Meaning | Colour |
| --- | --- | --- |
| MUST | Required for MVP. Without this the MVP cannot properly validate SafeIn5’s worker engagement, PULSE/SIGNAL loop or corporate pilot value. | Green |
| SHOULD | Strong MVP / Phase 1 value. Include where practical, but simplify or defer before compromising core MUST items. | Amber |
| COULD | Useful enhancement or Phase 2 candidate. Not required to validate MVP value. | Blue |
| WON'T | Not included in MVP. Future phase, Phase 2, or out of current tender scope. | Grey |
| DISCOVERY | Requires explicit discussion and decision during discovery workshop before final build scope is locked. | Orange |
| Platform Principle | Tender Position |  |
| One Platform, Two Operating Models | SafeIn5 should be architected as one platform that supports both Community and Corporate use without requiring a rebuild. |  |
| Community Platform | Free at point of use. Designed to grow adoption, learning, influence, and shared situational awareness. |  |
| Corporate Platform | Future monetised subscription model. Designed for controlled organisation/site use, SIGNAL intelligence, governance and operational learning. |  |
| Influence Before Compliance | SafeIn5 is not a traditional compliance reporting system. The product should encourage voluntary sharing, peer learning and safer decisions. |  |
| PULSE | Pause, Uncover, Learn, Shift, Echo — the frontline behavioural loop. |  |
| SIGNAL | Sense, Identify, Gather, Navigate, Alert, Loop — the intelligence and learning loop that converts signals into patterns and action. |  |
| Learn5 | Short, practical micro-learning content linked to PULSE, QR journeys, topics, sites and future learning themes. |  |
| AI Roadmap | AI, computer vision, predictive analytics and automated classification are future capabilities. MVP must not depend on them, but architecture should not block them. |  |
